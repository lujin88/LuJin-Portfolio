01 / Design principles

One portfolio world. Multiple authored voices.

This document is an evolution of the reverse-engineered foundation—not a redesign brief. Existing values remain evidence. The added rules prevent a future implementation from mistaking visual variety or legacy code for a mandate to flatten the work.

Type does hierarchy. Color does signaling.

Poppins carries the product voice for Display, headings, body, and UI site-wide. There is no second decorative display face. Blue-violet guides focus, labels, glows and selection; it does not erase hierarchy or become a blanket fill.

Image-led, 16:9, 43 / 57

Existing case-study sections use a full-viewport story stage, then a 43fr / 57fr copy-to-media split with 48–80px gutters; following sections may mirror the columns.

Motion explains, then stops

Pin-and-scrub storytelling, reveals and ambient movement support the narrative. At 640px or with reduced motion, pinning collapses to static stacks.

Theme layers inherit; they are not flattened

Case studies inherit Global Foundation rhythm, shell, interaction and motion. Their palettes, media and storytelling stay authored. Do not “correct” a theme with the global blue-violet.

Global Foundation vs Theme Layer

The architecture is two layers. Theme layers inherit the Global Foundation but are not flattened into it.

Global Foundation

Controls what repeats across the shared portfolio shell.

  • Typography and font weights
  • Spacing and layout
  • Global Page Frame (content alignment and starting rhythm)
  • Content Width / Text Measure (copy width inside a well)
  • Containers, radius, borders
  • Shared components
  • Interaction principles
  • Motion
  • Responsive behavior
  • Global shell (header mechanics, page field, blue-violet signal)

Theme Layer

May control what a case study authors for itself.

  • Case-specific palette
  • Section-specific colors
  • Illustrations
  • Media treatments
  • Storytelling motifs
  • Case-specific UI
  • Editorial treatments
  • Contained light/dark surfaces
Background Continuity Principle. Accent can change. The underlying visual world should remain continuous.

Sections may change accent color and case-study mood, but must remain part of the same spatial world. A colored section is an accent layer above the portfolio world—not a hard cut into another website.

Continuity includes:

  • background tone
  • surface depth
  • grain / texture
  • pattern language
  • spacing rhythm
  • section transitions
  • overall atmosphere

This does not mean every page must use the same background. Client Advisory navy and E.ON light sections are authored. Transitions should feel connected, not like a different website.

Spacing & layout

Repeated scale: 8 / 16 / 24 / 48 / 80 / 96 / 128px. Page padding is 24px; containers: 1440px main, 1040px editorial, 1600px HTML nav, 1800px React header. Do not force an artificial 8-point rewrite. The Global Page Frame below is the binding alignment rule for these existing values—not a second container system.

Global Page Frame

The Global Page Frame is the shared CONTENT FRAME for the portfolio. It records how the existing page pad, content containers and spacing scale already work together. It does not invent a cleaner grid, new breakpoints, or a universal Y coordinate. Theme Layers inherit this frame; they do not replace it, and they are not flattened into it.

Alignment principle. Global text/UI content should align to the shared page frame unless a documented Theme Layer or storytelling exception intentionally breaks the grid.
  • Respect the frame: text, headings, metadata, buttons and UI.
  • May extend beyond the frame: photography, illustrations, video, decorative shapes, arcs and other visual artwork.
  • Do not flatten: case-specific visual compositions must not be forced into one universal layout.

What counts as an intentional Theme Layer exception

A documented case or storytelling treatment that inherits the underlying well but authors a different interior inset, overlap, media overflow, or first-block composition. Extra case inset (for example a case rail or a theme-only pad) must not be promoted into the Global Page Frame, and other pages must not be forced to match it.

Content Width / Text Measure

The Global Page Frame defines where content sits (24px pad + 1440 or 1040 well). It does not define how wide a text block may run inside that well. Text-block width / reading measure was described conceptually (“controlled maximum width”, “controlled text width”, editorial text treatment) but was not numerically defined. This section records the three measures already used in the live portfolio. It does not add a third global container and it does not replace 1440 / 1040.

Wells vs measures. A well is a page/layout container. A text measure is a nested max-width on copy inside a well.
  • 1440px main well — media-led sections, 43/57 case rows, Index pin stages, About video inset. Not a reading measure.
  • 1040px editorial well — Lab / AI page frame, contact, HTML footer alignment, standalone editorial sections. May itself be the text block (Editorial Wide) or may contain a tighter nested measure.
  • Do not introduce a local arbitrary max-width (max-w-3xl as a page well, one-off pixel values, extra nested pads) without a documented reason in this section or a Theme Layer exception.

06 / Implementation rules

Audit → Normalize → Preserve → Apply.

This sequence is binding for Cursor or any implementation pass. It is a fidelity workflow, not permission to redesign.

  1. Audit. Compare live pages against this document. Classify every difference as global foundation, case theme, intentional exception, or implementation leftover.
  2. Normalize. Align only repeated global behaviors: shared type roles, spacing, container logic, borders, radius, interaction mechanics, motion safety and responsive behavior.
  3. Preserve. Retain authored case accents, editorial typography exceptions, case palettes, deliberate footer/header variations, imagery, background continuity and content hierarchy.
  4. Apply. Make the smallest implementation changes that restore consistency. Do not introduce a new visual direction, new global tokens, a new palette, or substitute components without evidence.

May unify

  • Repeated spacing, container and grid usage
  • Global Page Frame: shared content alignment and header-to-content rhythm
  • Content Width / Text Measure: Editorial Wide, Body / Standard, Reading / Narrow
  • Shared Poppins roles and global text contrast
  • Shared hairlines, radii, pill behavior and focus treatment
  • Global motion timing and reduced-motion fallbacks
  • Header mechanics where the live React header is source of truth

Must preserve

  • Client Advisory Theme Layer (ice / signal / navy tokens above)
  • E.ON Solar Theme Layer (navy, lavender, mint, red, light sections, Caveat)
  • Lab / AI Workflow blue-violet signaling and Poppins Display (editorial size)
  • Index experience periwinkle connectors and header-local #4a90ff
  • Continuous underlying world across accents and transitions
  • Case-specific footer and display-family differences recorded in the audit
Legacy safeguard. CSS merely present in the repository is not a token proposal. Do not promote unused or barely used declarations into Global Foundation, Theme Layer, or component tokens.

Explicitly excluded leftovers:

  • --color-bg-deepseek — unused; do not promote
  • .btn-primary-kling — unused; do not promote
  • Also unused unless markup proves otherwise: .tag-chip, .social-btn, .app-badge

07 / Audit notes

Differences with a reason stay different.

The live portfolio is the evidence. This section records intentional differences versus leftovers so an implementation pass does not flatten authorship.

Intentional differences

  • Global blue-violet vs header-local blue. Shell identity is #8B5CF6. React SiteHeader selected-language Check uses #4a90ff only. Do not collapse them.
  • Global blue-violet vs Index periwinkle. Experience timeline connectors use #7A7FDC / #3846D4 as an Index storytelling motif. Do not replace with #8B5CF6.
  • Global shell vs Client Advisory theme. CA navy, ice, signal and --ca-accent are Theme Layer tokens. They are not defects in the Global Foundation.
  • Global shell vs E.ON Solar theme. E.ON navy, lavender, mint, red and light sections are Theme Layer tokens. Local CSS names that contain “purple” still mean lavender.
  • One Display face. Index, About, Lab, AI Workflow, and Party Planner titles all use Poppins. Size tokens differ; the family does not. Theme hand accents (Caveat / Patrick Hand) stay local and are not Display.
  • HTML footer vs React footer. Compact HTML copyright on Index/About/Playground/AI Workflow; Client Advisory and E.ON use React SiteFooter with glow field. Shared copy (Playground link); different chrome.
  • HTML navigation vs React SiteHeader. HTML pages retain #site-nav (1600px / 80px / Poppins 700); Next.js hides it and mounts the 1800px React SiteHeader (Poppins 600, 80/96px). The React header is the live source of truth. Header chrome padding is not the content X-anchor; body copy follows the Global Page Frame.
  • Global Page Frame vs authored compositions. Text/UI align to the 24px + 1440/1040 well. Client Advisory, E.ON, Lab/AI, Index and About hero/artwork treatments may extend beyond that well. Different first-block Y positions are not automatically defects.
  • Wells vs text measure. 1440 / 1040 are containers. Nested copy uses Editorial Wide (1040 as the text block), Body / Standard (672), or Reading / Narrow (448). max-w-3xl (768) is a heading wrap limit, not a third well. Theme Layer ch/px measures on Client Advisory and E.ON stay authored.

Page-level implementation detail

  • About HTML nav contrast. About’s HTML nav uses 88% white and a text shadow; other HTML pages use 72% with no shadow. Documented until an audit establishes a deliberate shared rule. Live chrome remains the React header.

Legacy / unused — not tokens

  • --color-bg-deepseek. Historical CSS. Unused in current markup. Not Global Foundation. Not Theme Layer.
  • .btn-primary-kling. Historical button class. Unused in current markup. Not a component token.

Brand clarification

The global accent is blue-violet, not generic purple.

#8B5CF6 is the portfolio’s blue-violet signal. Use it for shared identity—focus, selection, Lab/AI eyebrows and arrows, restrained glows and related shell interaction states. It does not require individual case studies to adopt it, and it must not replace their authored blue, lavender, mint, red or other thematic colors.

Controlled vocabulary. In this Design System, call #8B5CF6 blue-violet. Do not rename E.ON lavender, Client Advisory blue, header-local blue, or Index experience periwinkle as blue-violet.
